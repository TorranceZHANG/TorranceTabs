# TorranceTabs 功能说明

参考 [Tab Out：Chrome 标签页智能管理工具](https://ata.atatech.org/articles/11020645212)的新标签页看板思路，独立实现按网址前缀自动归入 Chrome 原生标签组。

## 安装

1. 推荐使用[项目首页](../README.md)的安装脚本；手动解压发布包时，选择其中的 `extension` 文件夹。
2. 在 Chrome 地址栏手动输入 `chrome://extensions`。
3. 开启右上角“开发者模式”，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。
4. 首次安装会打开规则设置页。添加规则并保存，再打开匹配的网页即可自动归组。以后点击工具栏扩展图标，再点“分组设置”即可打开设置。
5. 打开新标签页即可进入标签看板。安装时 Chrome 会提示新标签页被扩展接管；如果另一个扩展也接管了新标签页，需要由你选择使用哪个。

这是无需构建和联网服务的 Manifest V3 扩展。支持 Chrome 110 及以上版本。加载方式参见 [Chrome 官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world#load-unpacked)。

### 更新与网页提醒授权

安装更新步骤见[项目首页](../README.md)。后续更新保持同一个加载目录，并在 Chrome 扩展管理页点击重新加载。首次从旧“前缀分组”的其他目录迁入时，不承诺沿用旧扩展身份、规则、稍后读或授权；先禁用旧扩展并保留原目录与注册，完成新配置后再决定是否移除。

要启用网页内浮层，请在设置页点击“授权网页内提醒”，并在 Chrome 中批准可选的网站访问权限。这个权限用于在网页里添加提示，默认不会自动授予；拒绝或撤销后，自动分组和一键去重仍可使用。

## 配置示例

| 网址前缀 | 标签组名称 | 颜色 |
| --- | --- | --- |
| `https://ata.atatech.org/` | ATA | 蓝色 |
| `https://github.com/` | 开发 | 紫色 |
| `https://github.com/openai/` | OpenAI 项目 | 青色 |

默认没有规则。设置页的“填入示例”只填写表单，保存后才生效。

- 使用完整的 `http://` 或 `https://` 前缀。前缀经过 URL 规范化后保存，域名不区分大小写，路径区分大小写。
- 采用字面前缀匹配。`/articles/` 匹配该目录；`/articles` 也会匹配 `/articles-old`。有目录边界要求时保留末尾 `/`。
- 同时命中时，最长前缀优先；多个不同前缀可以进入同一标签组。同名组的规则请使用一致颜色。
- 查询串、片段也可作为前缀的一部分；通用站点规则通常只需填写域名或路径，不必带追踪参数。
- 同一窗口内复用名称完全相同的已有组；颜色仅用于新建组，已有组的颜色及折叠状态保留。不会主动合并用户已有的重名组。
- 保存规则不扫描已有页面；点击“保存并整理当前窗口”可立即应用。
- 自动处理发生在标签创建、网址提交/加载完成、跨窗口附着等事件。不匹配时保持原组；禁用后暂停自动分组和手动整理。
- 跳过固定页、无痕页、分屏页及非 HTTP(S) 页面。共享标签组及其中的标签不参与整理；目标名称仅对应共享组时跳过。这些例外也适用于手动整理。

## 标签看板

新标签页按域名展示打开的网页，支持标题/网址搜索、重复 URL 标记和跨窗口定位。相同完整 URL 的多个标签合并为一条并标记数量；点击定位到其中一个。

“稍后读”只保存链接和标题，不关闭原标签。打开、移除清单项都由你显式操作。网址保留完整参数，界面简略显示域名及路径；清单与规则只存于当前 Chrome 配置的 `storage.local`。

## 一键去重

有三个入口，无需进入设置页：

- **工具栏图标**：点击“前缀分组”图标，面板中直接显示“一键清理重复页”大按钮、网页标签数和额外重复数。未固定图标时，可在 Chrome 的拼图菜单里把它固定到工具栏。
- **快捷键**：Mac 默认 `⌘⇧Y`（Command + Shift + Y）；其他系统默认 `Alt + Shift + D`。面板显示 Chrome 实际分配的快捷键；若冲突会显示“未分配”，点击“修改快捷键”即可调整，也可手动进入 `chrome://extensions/shortcuts`。快捷键只启动清理，工具栏图标角标显示实际关闭数量，点开面板可看详细结果。
- **标签看板**：顶部同名紫色主按钮，位于其他操作之前。

这些入口共用同一个清理任务；连续点击或同时使用快捷键不会重复发送关闭请求。关闭工具栏面板后后台任务继续，重开可查看状态。上次状态保存在 `storage.session`；若后台中断，显示结果未知且不会自动重试。快捷键参见 [Chrome Commands API](https://developer.chrome.com/docs/extensions/reference/api/commands)。

清理跨普通非无痕窗口执行，每个完全相同的 HTTP(S) 网址保留一份。比较完整 `tab.url` 字符串，查询参数和 `#` 片段不同就不会合并；不受搜索框筛选或自动分组开关影响。面板中的“额外重复”是网页快照统计，受保护的重复页不一定可关闭。

- 优先保留当前焦点窗口正在使用的那份，其次是固定、正在发声、其他窗口活跃、最近访问的标签；仍相同则保留 ID 较小的一份。
- 共享组、分屏及正在导航的页面会跳过，也不会充当唯一保留副本，因此受保护的重复页可能仍然存在。
- 只处理点击时的快照。关闭前发现网址、窗口、分组或使用状态变化会跳过；保留页失效时停止处理该网址，不冒险把最后一份也关闭。
- 点击后无需第二次确认；Chrome 如果针对未保存内容弹出原生关闭提示，请在 Chrome 中处理。程序等待该流程完成，不会自动重复发送关闭请求。
- 结果显示实际确认关闭、保留/跳过、失败及剩余重复数量。页面状态变化、原生提示取消或保护规则可能导致未能一次全部关闭，可刷新查看。

去重只比较网址，不比较页面内容、表单或登录状态。原生标签关闭操作使用 [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-remove)。

## 新标签重复提醒

新开标签首次出现 HTTP(S) 地址时，如果普通窗口中已有完全相同的完整网址，会在这个新标签的网页右上角显示小浮层。浮层不会打开新窗口、切换标签、抢焦点或遮住整页；后台打开的标签也只在它自己的页面中显示，当前正在浏览的页面保持原样。

- **跳转到已打开**：只有主动点击这个按钮后才切换到已有页面，并在复核后关闭这次新开的重复页。如果已有标签已关闭或跳转，保留新页面，可选择“保留新标签”。
- **保留新标签**：只移除浮层，页面继续使用，不重新加载，也不改变窗口或标签焦点。
- **× / Escape**：同样移除浮层并保留新标签，本次不再提醒。

这个开关独立于自动分组，默认开启。仍然按完整 URL 字符串比较，查询参数和 `#` 片段不同不会视为重复。固定页、无痕页、共享组、分屏页和非普通窗口在来源与目标两侧均跳过。

只检查新标签首次观察到的 HTTP(S) 目的地，不处理旧标签后续普通导航，也不追踪后续重定向；创建时没有网址的新标签会等待首次地址。提醒期间若手动导航、移动窗口或保护状态变化，操作前复核会保留当前页面。并发打开多个相同链接时，等待选择的来源页不会互相作为唯一已有副本。

原网页会正常加载，浮层不拦截网络请求。切换并关闭重复页时，Chrome 可能要求确认未保存内容；扩展只发送一次关闭请求，不自动重试，也不因等待关闭阻塞其他提醒的清理。关闭请求提交后，移除浮层无法撤销 Chrome 已收到的原生关闭请求。

需要可选的 `scripting` 与 HTTP/HTTPS 网站访问权限，使用 [Chrome 注入 API](https://developer.chrome.com/docs/extensions/reference/api/scripting) 在顶层网页的隔离环境添加 Shadow DOM 浮层。未授权、受限网页（如 Chrome 内部页、商店或禁止注入的页面）、权限撤销或注入失败时会保留页面并跳过，不改用独立窗口。原网页可以移除或遮挡网页内组件；这不是浏览器原生安全对话框。

浮层记录只存于 `storage.session`，处理后清理，浏览器重启或扩展重新加载后失效。后台记录 Chrome 文档 ID，确保同网址刷新后的旧按钮不会关闭新文档；不根据旧标签 ID 或相同 URL 猜测重绑。旧 1.3 弹窗和 1.2 整页提醒仅兼容已存在记录的处理与清理，不再创建新窗口或整页提醒。旧整页本地记录仍有效 30 天，过期在下次读取时删除。

## 权限与数据

- `tabs`：读取标签标题和地址，定位及分组。
- `tabGroups`：查找标签组、为新建组设置名称与颜色。
- `storage`：本地保存规则和稍后读清单。浮层的完整 URL、标题、随机 token、源标签及文档身份仅存在 `storage.session`，浏览器重启或扩展重新加载后清空。旧版未完成整页提醒的 URL/标题仍在 `storage.local`，30 天后失效，下次读取时删除过期记录。
- 可选 `scripting` 和 `http://*/*` / `https://*/*` 网站访问权限：只在检测到重复后安装提示组件，需在设置页由用户点击授权，也可撤销。采用 [Chrome 可选权限](https://developer.chrome.com/docs/extensions/reference/api/permissions)，不自动扩大已有授权。

扩展不调用 AI 服务，不发起外部网络请求，不采集正文、Cookie 或浏览历史。授权后仅向重复页注入浮层组件，不分析宿主页面内容；打开网页和稍后读链接时，Chrome 仍会正常访问目标站点。卸载扩展会清除本地数据；Chrome 原生标签组不会因此自动解散。

## 验证与限制

运行自动测试：

```sh
node --test tests/*.test.js
```

测试使用模拟 Chrome API，覆盖匹配、并发组创建、URL/规则变化、跨窗口竞争、跳过条件、稍后读并发更新、一键去重和重复提醒的选择/恢复/并发。浏览器界面预览使用合成数据，不等于真实 Chrome API 联调。更新后仍需手动重新加载扩展。

1. 保存 `https://example.com/ → 测试` 规则，在同一窗口打开两个该站标签，应只有一个“测试”组。
2. 加入更长的前缀规则，打开相应路径，确认进入更具体的组。
3. 在第二个窗口打开匹配页面，应在第二个窗口分组。
4. 检查固定页和未匹配页面保持原状；关闭自动整理后新页面不再分组。
5. 打开新标签页，确认搜索、跨窗口定位和稍后读的保存/打开/移除。
6. 授权后新开已经打开的测试网址，应仅在该网页右上角显示浮层；保留、× 或 Escape 只隐藏浮层，不切换焦点。主动点击“跳转到已打开”才切换并关闭新重复页。同网址刷新后的旧提示应失效。
7. 已有重复标签时，点击工具栏图标中的“一键清理重复页”或看板同名按钮，应只保留一份；不同查询参数或片段分别保留。可先关闭“新标签重复提醒”以准备测试用重复页。
8. 查看工具栏面板中的实际快捷键，关闭面板后按该组合，完成后角标显示实际关闭数；再打开面板可查看结果。取消分配时应显示“未分配”。

Chrome API 不提供原子的“仅当网址/窗口未变化时分组”操作。扩展在调用前复核状态，极短时间内的用户拖动仍可能产生竞争。后台意外终止时，尚未完成的任务可能需下一次页面事件或手动整理恢复；没有定时强制扫描覆盖用户手动分组。

规则入口为 `rules.js`，事件及消息入口为 `background.js`，串行分组和稍后读更新位于 `grouping.js`。
去重入口为 `deduplication.js`，`cleanup-controller.js` 统一工具栏、快捷键和看板的任务、状态与角标；`quick.html/css/js` 为工具栏面板。它们合并同一在途任务，不自动重试删除。
页内提醒入口为 `inline-duplicate-guard.js`，浮层为 `inline-prompt.js`；注入和实际网页关闭的等待在观察队列外完成。`popup-duplicate-guard.js` 和 `duplicate-guard.js` 仅兼容旧版提醒，新控制器启用 `legacyOnly` 禁止新建旧提醒。
